# Wedding Floral Questionnaire

A small bilingual (Czech / English) web app where couples fill in a floral questionnaire for their wedding.

- **Couple's page** – `index.html?w=<id>`: introduction, "How we work together", the questionnaire. Answers save automatically; inspiration photos can be attached. Each wedding has its own link with a random 12-character id.
- **Admin page** – `admin.html`: password-protected. Create a questionnaire (this generates the couple's link), see who opened, filled in and sent it, read and print the answers, view the photos.
- **Storage** – a Google Sheet with a Google Apps Script web app (`apps-script/Code.gs`). Answers are one row per wedding; photos go to a Google Drive folder. Free, no credit card.
- **Hosting** – any static hosting; set up here for GitHub Pages.

```
index.html, admin.html     the two pages
config.js                  settings: backend URL, name shown in the header, contact e-mail
assets/content.js          ALL texts in both languages + the questionnaire structure
assets/*.js, style.css     page logic and styles
apps-script/Code.gs        the backend – pasted into Google Apps Script
dev/                       local test server and backend tests (not needed for the live site)
```

---

## 1. Run it locally

Requires [Node.js](https://nodejs.org) 18 or newer. There are no dependencies to install.

```bash
node dev/server.js
```

Open http://localhost:4321/admin.html. The local admin password is read from `dev/.admin-password` (create the file if it's missing; it is git-ignored and never published). Local data is kept in `dev/.data/`; delete that folder to start fresh.

The local server runs the real `apps-script/Code.gs` against simulated Google services, so what you test is what you deploy. Backend tests:

```bash
node dev/test-backend.js
```

## 2. Set up the Google backend (once)

Use the Google account that should own the data, e.g. the florist's.

1. **Create a Google Sheet**, e.g. *Svatební dotazníky*.
2. In the Sheet: **Extensions → Apps Script**. Delete the sample code, paste the whole content of `apps-script/Code.gs`, click **Save**.
3. **Project Settings** (gear icon, left) → **Script properties** → **Add script property**:
   - Property: `ADMIN_PASSWORD`
   - Value: the admin password (at least 6 characters)
   - **Save script properties**.
4. Back in the **Editor**, choose the function **`setup`** in the toolbar and click **Run**. Google asks for permissions:
   **Review permissions** → pick the account → *"Google hasn't verified this app"* → **Advanced** → **Go to … (unsafe)** → **Allow**.
   This warning is normal for your own script. The log should say *"Setup done. Admin password is set."* – a sheet **Weddings** and a Drive folder **Wedding questionnaire – photos** now exist.
5. **Deploy → New deployment** → gear next to *Select type* → **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
   - **Deploy**, then copy the **Web app URL** (ends with `/exec`).
6. Check it: open the URL in a browser – it should show `{"ok":true,"service":"wedding-questionnaire"}`.
7. Put the URL into `config.js`:

   ```js
   apiUrl: 'https://script.google.com/macros/s/AKfy…/exec',
   ```

   While you are there, fill in `brandName` (shown in the header) and `contactEmail` (shown at the bottom).

> **"Anyone" access** only means the web app can be called without a Google login – needed for couples. It does not open the Sheet: couples can only reach their own wedding through its random link, and every admin action needs the password.

### Changing the backend later

Saving `Code.gs` does **not** update the live web app. After editing it:
**Deploy → Manage deployments → ✏️ (Edit) → Version: New version → Deploy.** The URL stays the same, so `config.js` doesn't change.

### Changing the admin password

Edit `ADMIN_PASSWORD` in **Project Settings → Script properties**. It takes effect immediately; no redeploy is needed.

## 3. Publish on GitHub Pages

1. Create a repository on GitHub. On a free account it must be **public** for Pages – that's fine: nothing secret is in the code (the password lives in Apps Script; `dev/.admin-password` is git-ignored).
2. Push this folder to it:

   ```bash
   git init
   git add .
   git commit -m "Wedding questionnaire"
   git branch -M main
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```

3. On GitHub: **Settings → Pages → Build and deployment** → Source **Deploy from a branch**, branch **main**, folder **/ (root)** → **Save**.
4. After a minute or two the site is live:
   - Admin: `https://<user>.github.io/<repo>/admin.html` – bookmark it; nothing links to it.
   - Couples get links like `https://<user>.github.io/<repo>/?w=9gz9pxms4bv2`, generated by the admin page.

A custom domain (e.g. `dotaznik.example.cz`) can be added under **Settings → Pages → Custom domain**.

## Everyday use

1. Admin page → **New questionnaire** → couple's names (required), wedding date, venue, contact, questionnaire language, internal note → **Create questionnaire**.
2. **Copy link** and send it to the couple. **Open** previews their page without marking it as opened.
3. The list shows each wedding's status: *Not opened yet → Opened → In progress → Submitted* (or *Edited after sending* if they changed answers after sending). Upcoming weddings are listed first; past ones are greyed out at the bottom.
4. **Answers** shows everything they filled in plus their photos (click a photo for full size). **Print** gives a clean printout. **Edit details** fixes names, date, etc.; **Delete** removes the wedding, its answers and photos (photos go to the Drive trash).

Couples can come back to their link any time; answers are saved as they type (and kept in the browser if they go offline). After sending they can still change answers and send again.

## Where the data is

- **Sheet "Weddings"** – one row per wedding. The `answers` column is JSON; read it comfortably on the admin page. Don't rename the sheet, reorder columns or edit the `id` column.
- **Drive folder "Wedding questionnaire – photos"** – a sub-folder per wedding. Photos are resized in the browser to max 1600 px (≈ 200–400 KB), max 10 per wedding.

## Changing texts or questions

- All wording, both languages: `assets/content.js`.
- Questions: the `FORM` list at the top of the same file (types: `yesno`, `radio`, `checkbox`, `textarea`, `fields`, `photos`; `showIf` shows a question only after a given answer). A new question needs a key in `FORM` plus its texts (`q.<key>`, options `o.<key>.<value>`) in both languages.
- After changing the site files, commit and push – GitHub Pages republishes automatically.

## Security notes

- The wedding link is the key to that wedding's answers: anyone with the link can see and edit them. Send it only to the couple.
- After 10 wrong admin passwords, admin sign-in is blocked for 15 minutes (for everyone).
- Pages are marked `noindex`, so search engines shouldn't list them.
